# Texture and style browser for the Illustrator panel: design plan

Status: design only (not built). Reason: RAM was too tight to run the panel's node UI tests next to the Varrenmoor exports, and the panel agent's files were
busy until late. Nothing here touches panel files yet.

## What exists today
* Building styles: `styles_ui.js` (Buildings tab) shows a `<select>` of `presets/building_styles/*.json` plus one preview PNG (`out/building_styles/<id>.png`).
* Textures: `presets/textures/*.png` (58 files, 256-ish px tiles) are only reachable as free-text names in the Roads tab (`surface`) and the Buildings tab
  (`roof_material`, `wall_material`); `object_edit.py choices` returns the allowed names.
* Town styles (`presets/town_styles/*.json`) are picked in the Town tab as a plain list.

## Goal
One browser with thumbnails so a GM chooses by looking, for four kinds of thing: ground/road textures, roof/wall textures, building styles, town styles
(whole-place presets such as `varrenmoor`: dirt roads, grass plazas).

## Layout (works at 340 px and 900 px panel width)
```
[ Textures | Building styles | Town styles ]        search box   [ tag chips ]
+--------------------------------------------------------------+
| grid of cards (2 columns at 340 px, 4 at 900 px)              |
|  card = 96 px thumbnail + name + 2 tags + "used by N objects" |
+--------------------------------------------------------------+
| detail strip for the selected card: big preview (tile x2x2),  |
|  mean colour, tile_ft, where it is used, [Apply to selected]  |
|  [Apply to all of kind...]  [Copy name]                       |
+--------------------------------------------------------------+
```
* Cards are plain DOM buttons (no canvas), lazily loaded `<img loading="lazy">`; the grid scrolls inside its own box (the panel's existing "no horizontal
  scroll, tables scroll in their box" rule).
* Tags come from a new sidecar `presets/textures/index.json` (generated by a script from file names + mean colour): `ground`, `road`, `roof`, `wall`,
  `water`, `field`, `ink`, `winter` (the `w_*` files). Building styles get tags from `category` and `kinds` already in the JSON; town styles from `parts`/`types`.
* Thumbnails: textures use the PNG itself (CSS `background-size` 96 px). Building styles use `preview` (missing previews show a placeholder and the id;
  `building_styles_preview.py render --only <id>` makes one). Town styles get a generated 2x2 swatch strip (street, plaza, building, field, water textures).

## Behaviour
* "Apply to selected" calls the existing jobs, no new Python: Roads tab selection -> `object_edit.py set-road --set surface=<name>`; Buildings tab selection ->
  `set-building --set roof_material=` / `wall_material=` / `style` (building_styles.py). Town styles -> panel state `town.fills.style` (and place.json
  `defaults.fills_style`).
* Guard rails: when a road class texture is `cobble`, `gravel`, `stone_slab` the card shows a small "paved" badge so an unpaved place (Varrenmoor) is easy to keep unpaved.
* "Used by": computed by `object_edit.py list-roads|list-buildings` (already returns the `edit` block) in one call, cached until the place changes.
* Keyboard: arrow keys move between cards, Enter applies, `/` focuses search.

## Work items
1. `generators/texture_index.py` (new): scans `presets/textures`, writes `index.json` (name, size, mean colour via PIL, tags, tile_ft hint). Test: every PNG indexed.
2. `panel/browser_ui.js` (new file, like `styles_ui.js`; registers a "Browse" section in the Buildings, Roads and Town tabs) + a small CSS block in `index.html`.
3. A `browse_list` job in `panelio.py` returning the three catalogs as JSON, so the panel does not read the filesystem itself.
4. `panel/test/test_browser_ui.js` in the style of `test_water_jobs.js` (mock host, check card count, filter, apply emits the right job); run `panel_ui_audit.mjs` at 340/600/900.
5. Docs: PLUGIN_GUIDE section "Browsing textures and styles".

## Risks
* Texture PNGs are not all square tiles; the 2x2 tiling preview exposes seams, which is a feature but may look noisy for `parch_*` and `ink_*` (hide those under an "advanced" chip).
* Foundry-side textures (Gemini candidates in `swarm/out/textures/`) are not in `presets/textures`; show them only after they are promoted.
