## 1. Scene flags (flags.levels-3d-preview)

Live dump of both working scenes (identical): `auto3d true, object3dSight true, enablePlayers true, exr "assets/ossuary-exchange-skybox3.webp", skybox "", renderBackground false, exposure 1, enableGameCamera true, enableFogOfWar true, grounding "", maxElevation 100000, enableRuler true, enableAnimationScripts true, renderTable "matcustom", tableTex "baileywiki-content/assets/modules/baileywiki-3d/models/black-tone-pure.webp", tableHeightmap "", tableHeightmapScale 1, tableColor "#341f0f", enableFog false, fogDistance 3000, sceneTint "#ffffff", timeSync "darkness", sunPosition 9, sunDistance 10, sunTilt 0, ambientLightIntensity 0, shadowBias -1.8e-05, showSceneWalls true, showSceneDoors true, showSceneFloors true, renderSceneLights true, mirrorLevels true, pp.enabled false, bloom false` [live].

Mapping to UI labels [doc]: `auto3d` = "Enable 3D on Load" (scene opens in 3D mode); `enablePlayers` = "Enable for Players"; `renderBackground` = "Display Background" (scene background image shown "as a flat surface"); `renderTable` + `tableTex`/`tableColor` = "Display Table" / "Table Texture" ("the table will be the size of the padding"); `exr` = HDRI (background when no skybox; lighting/reflections when a skybox is set); `skybox` = six-file cube map; `showSceneWalls/Doors/Floors`, `renderSceneLights` = "Render Walls / Doors / Tiles / Scene Lights"; `object3dSight` = "Use 3D Geometry for sight calculations"; `mirrorLevels` = "Mirror Levels Tile Visibility"; `sunPosition` 0 dawn .. 180 dusk, `timeSync` automatic sun from world time or darkness. `enable3d`, `grounding`, `maxElevation`, heightmap keys: names seen live; their semantics are not on the wiki page [infer: heightmap scale/`tableHeightmap` reshape the table; `maxElevation` caps token/tile elevation].

**Important [doc]:** "Turning on 3D will not make any changes to your original 2D Scene". 3D is a *view* toggled by the "Toggle 3D Mode" button under Token Controls; every scene can be viewed in 3D. A scene created without any levels-3d-preview flags has module defaults (`auto3d` off, so it opens 2D), but its 3D view still works if toggled. In 2D mode a model tile is only its placeholder 2D texture, which is why the white squares appeared: our tiles use `texture.src = modules/levels-3d-preview/assets/blank.webp` (a white image) with the model in `flags...model3d` [live, repo]. The wiki says exactly this: "the tile gets a placeholder 2D image, which Levels needs for visibility". So white squares in 2D are expected and not a bug; the cure for a clean 2D view is to not show model tiles in a flat scene [infer: also set tile `hidden`/`alpha 0` or keep model tiles only in the 3D scene].

Scene-level 3D defaults / "scene defaults": a new scene copies **no** 3D flags unless a template does; module-wide settings (graphics quality) are per-user client settings [doc]. If the user's world has a default scene template or a "Scene defaults" module that injects `auto3d: true`, the 2D map scene would open in 3D [TEST: create a scene with the bridge and read flags back].

## 2. What renders in 3D mode

| Element | In 3D view | Basis |
|---|---|---|
| Scene background image | Only with `renderBackground` true ("Display Background"), drawn as a flat plane at ground level. With it false the ground is the table (or nothing/skybox). Both can be on; the table is sized by `padding`. | [doc] |
| Table | Optional textured ground plane sized to the padding; `renderTable` values seen: `matcustom` (custom texture + `tableColor`). Heightmap table via `tableHeightmap` + `tableHeightmapScale` | [live], [doc] |
| 3D tiles (`model3d`) | Rendered as models: tile width/height = model X/Y footprint (fill type Fit/Stretch/Repeat), `depth` = Z, `elevation` in grid units/ft, `autoGround` drops it to the ground below, `autoCenter` re-centres the model | [doc]+[repo] |
| 2D image tiles | Rendered as flat planes at the level's bottom elevation (the wiki: "2D tiles sit at the bottom elevation set through Levels"). Background-type tiles render but the author says they flicker/pop when overlapping the background; prefer one background image or merge them (DF Architect) | [doc] |
| Drawings | **Not documented anywhere** in the wiki pages read. Our `Drawing` documents (road/water polygons, text labels) are 2D PIXI objects; assume they are **not** drawn in the 3D view [infer; TEST] | none |
| Walls | Rendered as 3D slabs if `showSceneWalls`; height from Wall Height top/bottom, thickness in the wall's 3D tab; our auto walls will show as thin untextured boxes (set `showSceneWalls false` on a map scene whose walls are only for vision) | [doc] |
| Lights | `renderSceneLights` shows Foundry ambient lights as 3D point lights (shadows are costly; per-light toggle) | [doc] |
| Grid | `Enable Grid` shows the grid on the 3D table/ground ("Show the grid in the 3D Scene") | [doc] |
| Tokens | A 3D model if set, else the token texture as a flat standing 2D figure ("standup"); `Scale` sets model size independent of grid size (not documented how) | [doc] |
| Templates | Measured templates have a 3D version (wiki page Measured-Templates, not read) | [infer] |
| Notes, regions | Not documented [TEST] | |

## 3. What our 2D details do in 3D, and workarounds

* **Drawings (roads, water, labels)**: likely invisible in 3D. Workarounds, best first: (1) bake roads/water/labels into the 2D background/table texture (our Illustrator export already is the full map image); (2) put them in the terrain/roads/water GLBs (world pack has roads.glb, water.glb with 3D geometry); (3) keep Drawings for the flat 2D scene only. [infer]
* **Background image**: in a 3D scene set `renderBackground: true` *only* if no terrain GLB tile covers the ground; the plane is flat at elevation 0 and would z-fight with a terrain GLB at the same height (see feedback on coplanar overlaps). With a terrain tile, use `renderBackground false`, and either bake shading into the terrain GLB's texture or use the shaded map as `tableTex`.
* **Table**: `tableTex` is a *tiled* texture path (the live value is a repeating black tone from the baileywiki module, not the map). A one-off full-map table texture needs scaling checks [TEST]. Heightmap table: black = high, white = low [doc, Tiles heightmap]; needs `tableHeightmap` path and scale [infer].
* **White placeholder squares**: expected in 2D mode (blank.webp). Leave as is on 3D scenes; do not push model tiles into the flat map scene.
* **Z-fighting**: roads/overlays on top of terrain need a real vertical gap (>= 0.05 m at map scale), not coplanar.
* **Second 2D scene variant** is the simplest reliable way to keep the flat Illustrator map with drawings and walls; `--scene-mode flat` below.

## 4. Scale, camera, tile conventions

* Scene px vs 3D size: the 3D world uses grid units, `grid.size` px = one square = `grid.distance` ft. Repo convention: 100 px = 1.524 m (5 ft = 20 px/ft) [repo]; pushes at other ppf scale tile sizes by `ppf` so models keep true size (`build_model_tiles`). Scene `padding` enlarges the table beyond the scene rect; the 3D camera is free, so padding only affects table extent and camera bounds [doc/infer].
* Tile `x,y` is the model **centre** in scene px (footprint centre; `autoCenter false` because the pack pivot is the footprint centre; vertical origin at the model base, `autoGround true` lifts to the surface below) [repo, live: the L marker tile at 1000,800 is 591 px wide]. `width` = model X, `height` = model Y, `depth` flag = model Z, all px.
* Rotation: `foundry-3d/README.md` says rotation 0 shows the model turned 180 from plan view (use 180); `make-scene.ps1`/`item.py`/the pack manifest say 0. Unresolved: the inspect scene (4 tiles at 0/90/180/270 with a coloured L marker, RED = model +Y) was pushed and its flags now match; read RED on screen [TEST]. Until then keep `tile_rotation_deg 0` (manifest) as is.
* Terrain mesh from the world pack: a GLB tile centred on the scene (terrain.glb footprint = full map), `elevation 0`, `autoGround false` (nothing below it to snap to; true would drop it onto the table, usually the same result), `autoCenter false`, `collision true`/`sight true` only if tokens must walk on it. Heightmap table is the alternative for a *cheap* relief (one texture), but tokens and tiles then use `autoGround` against that relief; the GLB gives exact baked heights, roads cut and shaded textures [infer].
* Supported model formats: GLB, glTF, FBX [doc]. Draco yes; meshopt/KTX2 probably not (see WORLD_PACK.md).

## 5. Recommended push strategy

(a) **Flat 2D map scene** (`foundry_push.py push-scene ... --scene-mode flat`, the default for new scenes): `auto3d false, enablePlayers false, renderBackground false`; background image, calibrated grid, walls, Drawings (roads/water) as today. No model tiles. The 3D toggle still exists but the scene opens flat and nothing is changed by toggling.

(b) **3D scene** (`push-models ... --scene-mode 3d`, default for push-models): flags = the live template (`auto3d true, enablePlayers true, renderBackground false, renderTable matcustom + tableTex/tableColor, exr, showSceneWalls/Doors/Floors true, renderSceneLights true, mirrorLevels true, sunPosition 9, ambientLightIntensity 0, maxElevation 100000`, plus `object3dSight, enableGameCamera, enableFogOfWar, enableRuler`). Contents: terrain GLB tile + building GLB tiles; shading baked into the terrain texture; pass `--scene-flag renderBackground=true` only for a 2D-texture-only ground. Override any value with `--scene-flag key=json` (repeatable). Note `tableTex` and `exr` point to assets that live in the user's world (baileywiki module, assets folder); on another world override them.

Existing scenes are only re-flagged when `--scene-mode` is passed explicitly, so hand tuning is never overwritten silently.

## 7. Bake the finished 2D map into the 3D ground texture (no live push)

Drawings, labels and fills are not rendered by 3D Canvas, so the finished map is baked into the scene's table texture instead.

1. Render the map PNG without Illustrator: `python illustrator/generators/region_render.py --child ID --scale 20 --grid 5` writes `<prefix>.png` (headless, `svg_raster.py`, page at `--png-dpi` 120). The result JSON gives `window_ft`, `png_dpi` and `page_margin_pt`. (An Illustrator export of the open document works too; give its dpi.)
2. `python illustrator/generators/foundry_push.py bake-texture --place ID --image map.png --crop-margin-pt 36 --dpi 120 --window x0,y0,x1,y1 [--name ground] [--publish]`
   crops the paper margin, checks the image against the window in feet (px per ft must agree on both axes), converts to a versioned webp under `art/<place>/maps/` (local `world/<place>/export/baked/` unless `--publish` copies into the shared assets folder) and writes `bake.json` with the footprint in feet, px/ft and the exact scene flags (`renderTable matcustom`, `tableTex <path>`, `renderBackground false`). It makes no Foundry call.
3. Apply it with a later push: `push-models ... --table-texture assets/varrenmoor-3d/art/<place>/maps/ground_v001.webp` (same as `--scene-flag renderTable="matcustom" --scene-flag tableTex=...`).

Open (TEST live): whether 3D Canvas tiles or stretches `tableTex` over the padded table, and at what scale. The table is sized to the scene padding, so the bake records the footprint in feet; if the table is bigger than the map the texture will have to be placed on a flat ground tile at that footprint instead (a plane tile at elevation 0 under the terrain GLB would z-fight, keep it 0.05 ft below). Roads/water as real geometry stay in the world pack GLBs; this bake carries the paper look only.

## 8. Lighting: Illustrator config -> Foundry (`generators/foundry_lighting.py`)

Source: `world/<place>/panel_state.json` "lighting" (or a lighting JSON): sun azimuth (compass bearing OF the sun, 225 = SW), altitude (30), colour (#fff1d0), intensity, ambient 0.35, point lights {x,y,radius,height,color,intensity}.
* 3D scene flags (`push-models --lighting bridgehollow`, new scene or with `--scene-mode 3d`): `sunPosition` (hour, found by inverting the module's time->angle table; 225/30 -> 15.34), `sunTilt` (0.564), `sunDistance 10`, `timeSync off` (so darkness/world time does not move the sun), `sceneTint` = sun colour, `exposure` = sun intensity, `ambientLightIntensity` = ambient. Derivation and the rig model are in the module docstring; `test_foundry_lighting.py` round-trips the vectors. Verified live: the module's sunlight world position is exactly (-0.61, 0.5, 0.61) x 10 for 225/30.
* Skybox: `skybox.py generate --lighting bridgehollow` puts the sun disc at the same bearing/altitude (sun_az = bearing - 90 from east, sun_el = altitude).
* Point lights: `push-lights --lighting bridgehollow` creates the 2D lights at the same positions (config frame minus the child's `origin_ft`), radius -> dim, 0.4 x radius -> bright, plain, no particles. The bridgehollow config currently has no point lights, so only the interior hints (hearth/window) exist.
* Flat scenes: the 2D map already carries baked shadows and glow, so the scene gets `environment.darknessLevel 0` and global light on (`--lighting`); no sun in Foundry.
Look check: SW-facing walls lit, NE roof slopes darker; with ambient 0.35 the whites (plaster) are close to clipping under ACES: lower `exposure` or the ambient flag if too bright.

## 9. Water shader (flowing, rippled water): research and chosen approach (2026-11-08)

Source read: the module code on Vega, `Data/modules/levels-3d-preview/scripts/` (3D Canvas 9.0.29, bundled three.js **r132**: `main.js`, `entities/tile3d.js`, `shaders/ShaderLib.js`, `apps/QuickTerrain.js`, `lib/GLTFLoader.js`). Nothing was run in Foundry for this section; items marked TEST need the live check below.

What 3D Canvas gives us [code]:
* **three.js is exposed**: `game.Levels3DPreview.THREE` (also `CONFIG`, `tiles`, `shaderHandler`, `helpers`). Tile objects are `game.Levels3DPreview.tiles[tileId]` (Tile3D: `.mesh` = the model root, `.tile.document`).
* **Per-tile shaders flag** `flags.levels-3d-preview.shaders` = `{shaderName: {enabled, ...uniforms}}` is applied to every mesh of a model tile (`ShaderHandler.applyShader` -> `onBeforeCompile` injection into the standard lit material). Built-ins: `water` (sine vertex displacement, needs a dense mesh and a box `dynaMesh` tile), `ocean` (3 Gerstner waves + optional white foam), `textureScroll` (UV scroll), `distortion`, `wind`, `idle` ... The registry is `game.Levels3DPreview.CONFIG.shaders.shaders` (a plain object, extendable at runtime, but nothing registers our shader at startup). The built-ins have no flow-map, no shore mask, no depth tint. Quick Terrain's water button makes a 100 ft box tile, not our mesh.
* **Per-tile animation script** `flags.levels-3d-preview.onAnimation`: a function BODY called as `fn(delta)` every frame with `this` = the first child of the tile's model after load; gated by the scene flag `enableAnimationScripts` (default true; our scenes have it true). It runs on every client (the code travels in the tile document). Any tile update destroys and reloads that tile's 3D object.
* **glTF**: r132 `GLTFLoader`: KHR_texture_transform (static only), KHR_materials_{clearcoat,ior,sheen,specular,transmission,volume,unlit}, EXT_texture_webp, draco, meshopt, **no KHR_animation_pointer** (no animated UV or material from the file). Node TRS animations play through an `AnimationMixer` (tile flags `animIndex`, `animSpeed`). Custom attributes `_NAME` load as geometry attribute `_name` (lower case). Vertex colours are honoured (`COLOR_0` multiplies the base colour). Node `extras` end up in `object.userData` (doors use this).
* Video textures exist (`helpers.js` `THREE.VideoTexture`, for tile/token textures and shader texture uniforms); a WebM on a model material is not a documented path and there is no sprite-sheet flipbook for model materials.
* Transparency: GLB `alphaMode BLEND` -> `transparent true`, the module forces `depthWrite false` for blended materials; transmission/refraction are loaded but cost a second pass and need the environment: not used.
* No paid module needed: `canvas3d-premium` is installed on Vega but none of this uses it.

Options weighed:

| | Needs | Verdict |
|---|---|---|
| (a) macro / world script that finds water meshes and patches the material | code that runs at canvas ready on EVERY client (world script = edit `world.json` + restart; macro = per client, manual) | works, install is fragile |
| (a') **the same patch shipped as the tile's own `onAnimation` flag** | nothing installed: `install-water` / `push-models` write the flag | **chosen**: players run it, idempotent upsert by pipelineId, parameters in `flags.varrenmoor.water` on the same tile |
| (b) glTF animation (node translate of a tiling normal map) | KHR_animation_pointer (absent in r132) | impossible (a node can move, a texture cannot scroll) |
| (c) looping WebM / animated WebP texture | video material path, no lighting response, seams, big files | rejected |
| (d) own Foundry module | version bump + deploy on Vega | not needed |
| built-in `shaders: {ocean / textureScroll}` flag | zero code | fallback idea only: no river flow, no foam mask, needs dense geometry |

How it works (`foundry-bridge/water/vb_water.js`, about 9 KB, three.js r132): on its first frame the script finds meshes whose material is named `VB_water_*`, clones the material, sets `transparent`, `depthWrite false`, double sided, and patches it with `onBeforeCompile` (the lit MeshStandardMaterial stays: sun, shadows, environment reflections, fog and tone mapping all apply). Fragment: 4 travelling sine layers with analytic normals (procedural, no texture, no tiling seams, amplitude proportional to wavelength), two-phase flow advection for rivers (the pattern follows a speed that changes along the channel), plain scroll along the wind for pond / lake / ocean, foam (shore band x noise, crest foam, rapids foam), opacity clearer at the banks plus a fresnel lift, depth tint, rougher where foamy. Per frame: one uniform write; GPU: 2 pattern evaluations x 4 sines for rivers, 1 for still water. Parameters are re-read from `flags.varrenmoor.water` every 30 frames (a changed value only touches uniforms). Per-vertex data comes from the glTF attribute `_VBWATER` (WORLD_PACK.md, water entity). Not done: vertex displacement (needs a tessellated mesh and the model scale; normals only) and refraction.

Commands: `foundry_push.py install-water --scene-uuid U [--place P] [--dry-run] [--enable-scripts]`; `foundry_push.py set-water --scene-uuid U --preset river --set flow_speed=2 --set foam=0.5 [--force]` (live; the tile reloads once). Both touch only tiles flagged by the pipeline (`model:<place>:...`) whose file is the water layer; `push-models` / `push-scene-3d` decorate the water tiles automatically. Panel: Water tab, group "3D water in Foundry". Tests: `python illustrator/generators/test_water.py`, `node illustrator/panel/test/test_water_jobs.js`, `node --test foundry-bridge/water/vb_water.test.mjs` (patches a real r132 material and checks every injection point against the module's own shader chunks).

## 10. Collision flag, sight flag, and Foundry walls (2026-11-09, 3D Canvas 9.0.29 source read on Vega + live on the Dyers test scene)

Source (`handlers/interactionManager.js`, `entities/tile3d.js`, `entities/token3d.js`):
* `collision` (tile flag, module default TRUE, our pack tiles used to be false): the tile's sight mesh joins the `move` raycast set. Effects: (1) a dragged token is raycast against collision tiles, the table, walls and the board, so it SNAPS TO THE HEIGHT of whatever collision geometry is under the cursor (terrain relief, road, floor); with collision off on terrain a token drags along the table plane and falls through the ground; (2) for PLAYERS (not the GM) a token move is refused when a ray from the old to the new position hits the move set and the scene flag `object3dSight` is on (ours is): buildings and walls physically block players; (3) the grounding check (`tokenNotGrounded`) and the height indicator ray downward against the move set; (4) native 3D door click: the hover filter drops tiles without collision unless the Tiles layer is active. It does NOT change what is drawn, does not block line of sight, does not touch light.
* `sight` (tile flag, left OFF): the mesh is sent to the 3D vision web worker (`sendToWorker`) and blocks 3D vision. This is the expensive one (worker memory + per-token raycasts) and is the module's own mechanism, separate from Foundry walls. Not used.
* Cost: none per frame. The BVH (three-mesh-bvh) and the cloned `sightMesh` are built for every tile whether the flag is on or off (`getSightMesh`); `sightMeshComplexity` < 1 simplifies that clone (load-time cost, coarser collision proxy). A move check is one BVH ray. Tiles whose glTF has node extras (all building tiles with doors: `hasTags`) are cloned node by node on every tile/wall update, which is why the move set on Dyers has 378 entries for 4 collision tiles.
* Foundry wall documents are also meshes (`Wall3D`) and, when `move > 0`, join the same move set WITHOUT a BVH: every wall is one more ray target.
* Gotchas: a roof or tree-canopy tile with collision on catches a dragged token from a top-down camera, so roofs/foliage stay off; water has no standing surface (off); the padding apron / table is always in the set (off). A hill steeper than the token height gap can block a PLAYER move because the ray runs token-eye to token-eye (flat town: fine; check steep terrain). An OPEN door node sets its own collision false (userData), so a model door opens for movement and for the native click.
Measured live (Dyers test scene, GM tab, 14 merged layer tiles + 9 foliage chunks; 60 Hz vsync caps frame time at 16.7 ms in both states, so CPU numbers instead): `renderer.render` CPU mean 0.29 ms (off) vs 0.37-0.38 ms (collision on + 175 walls), p95 2.9 vs 3.2 ms; one move ray 1.1 ms vs 1.5-1.7 ms; one downward ray (grounding) 1.4 ms vs 2.1 ms; geometries 240 -> 417 (175 wall meshes); JS heap 680 -> 695 MB after GC (transient 840-1330 MB while the tiles reload after the flag update). Conclusion: collision costs well under 1 ms per raycast and nothing per frame; rays only run on a token drag, a player move or token grounding. Merged big tiles are fine (BVH); per-building tiles add one BVH each to the ray set. Not measured: merged vs split on one map, tokens on steep roads (no token on the test scenes).
Defaults chosen (foundry_collision.COLLISION_DEFAULT): ON terrain roads plazas fields fences walls bridges buildings props; OFF roofs foliage water padding. `--collision` on push-models/push-scene-3d, `set-collision` for existing tiles, panel Foundry tab "Collision and walls".

Walls (foundry_collision.py, `push-walls`): the model alone cannot block Foundry token vision/light/sound, so Wall documents are generated, flags.varrenmoor.pipelineId `wall3d:<layer>:<id>:<n>` (the 2D push-scene walls are `wall:`; never mixed). Values 0 none, 10 limited, 20 normal. buildings: move/sight/light/sound 20 around the footprint (collinear vertices merged), each EXTERIOR door = a closed door wall (door 1, ds 0, flags.varrenmoor.doorId = the model's door id) cut into the nearest edge; walls (town walls): same, gates (kind has "gate") are door walls; fences: move 20 only; trees: stands of >= 5 trees within 30 ft of each other become one convex ring (grown 8 ft, <= 14 vertices), move 0, sight 10, sound 10, light 0 (a ray that crosses a stand crosses two limited walls = blocked; looking from outside into the first edge, or from inside out, is not); water: sound 10 only (a limited sight ring would blacken every 40 ft river from bank to bank; override `--wall-profile water:sight=10`). Counts on Dyers Walk: 150 building walls (25 buildings, 25 door walls) + 25 tree walls (9 stands) = 175; the bridge scratch river = 16 water walls. Verified live (Foundry `testCollision`): a ray from outside into a house is blocked for move, sight, light and sound, also at a closed door; with the door wall at ds 1 all four pass; across a tree stand sight is blocked (sound partly), movement free, a ray from outside to the stand centre is not blocked. The wall door state is NOT synced with the model door (`modelDoors.<id>.ds`): opening the model door by click leaves the wall door closed until the GM opens it too (flags.varrenmoor.doorId is stored for a later sync hook). Tree positions come from `--foliage-json` / world/<place>/foliage.json / scatter/foliage.json / pack entities (low plants skipped); merged foliage GLBs carry no per-tree positions.


## 11. Lights, shadows, global illumination and what they cost (2026-11-09, 3D Canvas 9.0.29 source read on Vega + live on ZZ Dyers Walk 3D Test, GM tab)
Source (`entities/light3d.js`, `systems/globalIllumination.js`, `main.js`, `settings/performancePresets.js`): there is NO scene flag for a light cap, shadow map size or shadow on/off. What exists:
* Scene flags (flags.levels-3d-preview): `renderSceneLights` (default true; false = no Foundry light is drawn in 3D), `ambientLightIntensity` (0..1, one THREE.AmbientLight, added only when > 0) and `ambientLightColor` = the "global illumination"; sun = `sunPosition` (hour 0..24 through the time spline), `sunTilt`, `sunDistance` (0 = sun off; also sets sun castShadow false), `exposure` (sun intensity AND tone-mapping exposure, ACES filmic), `sceneTint` (sun colour), `timeSync` (off / darkness / time), `shadowBias`, `exr` (HDRI, lights and reflects when a skybox is set), `dynamicSky.*`, `enableFog`/`fogDistance`, `bloom*`, `pp.*`. Darkness level: with timeSync `darkness` a darknessLevel change rewrites `exposure` to 0.2 + 0.8 x (1 - darkness).
* Per light: `levels-3d-preview.castShadow` (default FALSE, we never set it unless asked), `tilt`, `visibleWhenDisabled`, particle flags. Intensity = alpha x 9, radius = max(dim, bright) in scene units, decay = (dim / (bright + 10)) x 2. A hidden AmbientLight gets `light3d.visible = false` each frame, so three.js leaves it out of every shader: hiding is the cheap, reversible way to cap lights.
* Client (per browser, NOT scene) settings: `shadowQuality` (0 none, 2 low, 4 medium, 8 high, 16 ultra, 32), sun shadow map = 1024 x quality px, light shadow cube map = 256 x quality px per face, `softShadows`, `lightCacheSize` (world setting, default 4; players capped at 4), `resolutionMultiplier`, `enableEffects` (particles). Performance presets: verylow/low shadowQuality 0, medium 2, high 4, veryhigh 8.
* three.js r132 is a forward renderer: every VISIBLE point light is looped over for every lit pixel of every material, light count changes recompile the shaders, and every shadow-casting point light renders the scene 6 more times. The shader has a hard ceiling: all lights' uniforms must fit MAX_FRAGMENT_UNIFORM_VECTORS (1024 on the test GPU).

Measured live (Dyers scene, camera fixed, 1858x937, 60 Hz vsync, shadowQuality 0; GPU time = EXT_disjoint_timer_query over all passes of a frame; renderer.render CPU stayed 3.5-6.8 ms and did NOT follow the light count, the cost is on the GPU; "visible" = visible THREE lights incl. 8 cache lights + sun + ambient):

| visible lights | GPU ms/frame | fps | note |
|---|---|---|---|
| 14 (0 point lights, ambient 0.55) | 5.8-5.9 | 58 | ambient + sun only |
| 30 (16 lights) | 6.2 | 58 | |
| 50 (36 lights) | 8.1-8.5 | 56 | |
| 86 (all 72 pack lights) | 14.0-15.4 | 56 | 2.5x the empty scene |
| 142 / 156 (128 / 150 lights) | 15.9 / 16.2 (p95 21) | 54-57 | |
| 206 (200 lights) | 28 | 33 | some materials already failing to link |
| 306 (300 lights) | scene draws NOTHING | | 16 shader programs failed to compile (fragment uniform limit), screenshot lighting_dyers_300_lights_blank.jpg |

Auto mode at 300 lights: global = 5.8 ms, 58 fps; hybrid (16 lights + ambient 0.45) = 5.8 ms. Rough rule used for the cost hint: +0.02 x an empty scene per light above about 30 lights (0.13 ms here); this depends on GPU and screen size and is a guide only.
Shadows: with shadowQuality 2 and 4 lights flagged castShadow (72 lights): 30 fps (from 59), 2871 draw calls and 5.6 M triangles per frame (from about 530 and 0.5 M); the first enabling stalled the page for over 45 s (shader recompile with 72 lights). Verdict: never cast light shadows on a big map; the sun shadow alone (quality 2) cost no visible fps here.
Module quirks found: (1) a DELETED light stays in the 3D scene as a ghost (Light3D is destroyed into a light cache but `sceneLights` and the visible light remain): after deleting 228 lights the scene still counted 306 visible lights and stayed blank until `canvas.draw()` (scene redraw, no reload) rebuilt it; so a push that prunes lights frees nothing in an open GM tab until the scene is redrawn, whereas hiding (set-lighting) frees it at once. (2) Creating many lights at once as visible can blank the scene before any cap can run: create over-budget lights hidden or do not create them (push-lights with `--max-lights` creates only the budget). (3) The GM tab can fall back to the world's active scene after a long stall.
Pipeline support (`foundry_lightbudget.py`): `--max-lights`, `--lighting-mode lights|global|hybrid|auto`, `--exclude-types`, `--light-radius-scale`, `--light-intensity-scale` on push-lights / push-scene-3d; `set-lighting` on an existing scene (hide over-budget lights, flags.varrenmoor.budgetHidden / base, scale from the stored base, `--light-shadows`, `--time-of-day dawn|noon|dusk|night`, `--ambient`, `--ambient-color`, `--sun-strength`, `--sun-color`, `--render-scene-lights`); priority plaza 100 > lamp 80 > 2D config point 75 > door 70 > hearth 60 > window 30, farthest-point thinning inside a kind. Auto thresholds: up to 64 all lights, 65-150 hybrid (16 lights, ambient >= 0.45), above 150 global (ambient >= 0.55), because 72 lights already cost 2.5x and 200+ break. Panel: Lighting tab, last block. Restored after the tests: all 72 Dyers lights, the scene flags and the environment are identical to the dump taken before (checked by diff), shadowQuality back to 0, the test lights `light:stress:*` deleted.

## 12. Sun, shadows, fog and sky: what 3D Canvas has, why Dyers looked flat, what the pipeline now writes (2026-11-09, 3D Canvas 9.0.29 source fetched from http://vega:30000/modules/levels-3d-preview/scripts/..., live on ZZ Dyers Walk 3D Test)
File:line below are in that module source (`systems/globalIllumination.js` = GI, `main.js`, `entities/tile3d.js`, `entities/light3d.js`).

**Sun (GI).** One THREE.DirectionalLight (GI:98). Scene flags: `sunPosition` hour 0..24 mapped to an angle by a spline (GI:87-95), `sunTilt` (x-rotation, tilt x pi/2, GI:154), `sunDistance` (GI:149; 0 = sun OFF and castShadow false, GI:173-174), `sceneTint` = sun colour (GI:148), `exposure` = sun intensity AND `renderer.toneMappingExposure` (GI:151-153, 178; ACES filmic, main.js:1173). There is no separate azimuth/elevation: the pipeline converts bearing/altitude with `foundry_lighting.sun_to_3d`. `timeSync` `off|darkness|time` (GI:242-251; default `darkness` unless SmallTime): with `darkness` a darknessLevel change overwrites `exposure` to 0.2 + 0.8 x lightness (GI:226-238; main.js:1152 setExposure ignores the flag then); `time` sets sunPosition from game.time.worldTime (GI:182-224, no Simple Calendar needed). The pipeline writes `timeSync off`.
**Ambient / hemisphere.** `ambientLightIntensity` + `ambientLightColor` = one THREE.AmbientLight, added only when > 0 (GI:28-35). No hemisphere light. BUT the skybox/exr is also the scene `environment` (main.js:1224-1228 / 1199-1203), i.e. image-based light on every material: a second, fixed fill the flags cannot lower, except by choosing a darker sky image. So an ambient of 0.35 on top of the environment (what Dyers had) leaves almost no contrast; the pipeline now writes 0.06 to 0.17.
**Shadows.** The sun casts only if the CLIENT setting `shadowQuality` > 0 (GI:137, set once at init GI:134-145: map = 1024 x quality px, `shadow.bias` = flag `shadowBias` default -0.00018, camera far 100, near 0.1; frustum = scene size x 1.5 per axis, GI:107-113). There is NO scene flag for shadow quality, map size or on/off; `renderer.shadowMap.enabled = true` always (main.js:598), type PCF or PCFSoft by client `softShadows` (main.js:608). Per tile: `levels-3d-preview.castShadow` default TRUE (tile3d.js:376; applied to child meshes 1180, instanced 1280/1406, 1529), receiveShadow always true (tile3d.js:1181 etc.), so buildings, trees, roofs and terrain already cast and receive; no tile flag needs to be written (`set-sun --ground-cast off` optionally stops terrain/roads/plazas/padding casting). The background plane and table receive shadows (main.js:976, 1041). Per light: `castShadow` default false (light3d.js:149; also needs quality > 0). `shadowQuality` is read in `init()`: after changing it a scene redraw (`canvas.draw()`) or reload is needed.
**Fog.** Flags `enableFog` (default false), `fogColor` (default #000000), `fogDistance` (scene px, default 3000) (main.js:846-868, 897-908 `setFog`, live on flag change main.js:2012). It is `THREE.Fog(color, near = 1 unit, far = fogDistance / 1000)`: LINEAR, near fixed at 1000 scene px (1 unit = 1000 px = 50 ft at 5 ft per 100 px); no FogExp2, no density, no height fog, no darkness/time link. Side effects: `camera.far = fogDistance/1000` (else 100), and while fog is on the scene background is the flat fog colour (main.js:900, 1167, 1203; loadEXR 1231 only builds the sky cube when fog is off): the sky IMAGE is hidden (it still lights the scene). Found on Dyers: `enableFog true, fogColor #c9dcee, fogDistance 98000` = no visible fog but a flat pale-blue sky instead of the skybox. There is also `dynamicSky.*` (Sky.js shader, GI:37-85, defaults GI:253-266: turbidity, rayleigh, mie, skyTint, stars, clouds); a weather system is commented out (main.js:880), so there is no weather feature beyond sun/exposure/dynamic sky.
**Sky.** `exr` (equirect image or .exr) = background (fog off) + environment light; `skybox` = 6-file cube = background only when no exr (main.js:1161-1210). Night therefore needs a dark sky IMAGE and low exposure; `skybox.py` has procedural `night` (stars + moon), `dusk`, `overcast`.

**Diagnosis (live, GM tab, before any change).** Scene flags were fine (sunDistance 10, sunPosition 15.34, sunTilt 0.564, exposure 1, ambient 0.35, default shadowBias) but the client setting `shadowQuality` was 0, so `shadow.mapSize` was 0 and no shadow was drawn (`sunlight.castShadow` true, map 0). Even with quality 4, exposure 1 + ambient 0.35 + the sky's image light gave no visible shadows (`sun_before_oblique.jpg`); with ambient 0 to 0.1 and exposure 1.3 the tree and building shadows read. Frustum: scene 6130 x 7236 px gives a shadow camera of about 10.9 x 9.2 units (read live: left/right +-5.43, top/bottom +-4.60, centre (4.67, 5.52)), which covers the pack and the near apron. Ground materials are MeshStandard and receive shadows; nothing is unlit.
**Cost (live, GPU timer = EXT_disjoint_timer_query_webgl2 around 20 renders, 1858x937, 72 lights, camera fixed; three runs each, ms/frame):** quality 0 (no sun shadows) 12.9 / 12.7 / 11.5, quality 2 11.7 / 11.8 / 11.2, quality 4 12.3 / 12.4 / 11.0, quality 8 12.3 / 12.4 / 13.3. Baseline run before the sunset test: 12.9 (off) vs 13.5 (q4). The sun shadow pass is inside the run-to-run noise (+0 to +1 ms of about 12): on this scene sun shadows are affordable at quality 4 (4096 map over 9 x 11 units, about 2 px per ft). Point-light shadows stay off (section 11). Client setting, per browser: each player (and the GM) sets Configure Settings > 3D Canvas > Shadow Quality to 4 (the Medium preset; performance presets: medium = 2, high = 4); 0 = no shadows for that person.

**What the pipeline writes now** (`foundry_sun.py`, command `set-sun`, presets `illustrator/presets/lighting/*.json`, dry run unless `--apply`): `sunPosition/sunTilt/sunDistance 10/timeSync off/sceneTint/exposure`, `ambientLightIntensity/Color` (low), `shadowBias` (-0.0003, -0.0004 at low sun), fog `enableFog/fogColor/fogDistance` (>= 4000 px), optional sky `exr` (`sun_<preset>.webp` built by `--make-sky` through skybox.py with the preset's sun bearing/altitude, published like `skybox.py set-flag`). The first apply stores the previous values in `flags.varrenmoor.sunBackup`; `--restore` puts them back (new keys are removed with `-=`). The result carries the client instruction and a cost hint. `push-scene-3d --sun-preset NAME` writes the same flags in its flags step. Presets: dawn, morning, noon, afternoon (default, sunny), dusk, night (moon, deep-blue starry sky), foggy_morning (low pale sun, dense fog 7000 px, soft grey ambient, overcast sky), warm_sunset (sun 7 deg in the west, orange, ambient #ffb27a, golden fog 26000 px). Fog is OFF in all but the two special presets (it hides the sky image, see above); turn it on per scene with `--fog on --fog-color <sky horizon colour> --fog-far N`.
**Verified live on ZZ Dyers Walk 3D Test:** `set-sun --preset warm_sunset --apply` changed the flags and the open GM tab followed without a reload (read back from the page: exposure 1.35 then 1.55 after the preset retune, fog near/far 1 / 22 then 26 units, ambient 0.1 then 0.17), warm gold light and sky, tree and building shadows on the ground (`sunset_*.jpg` in `out/foundry_screens/`; the sun shadow map was forced to quality 4 from the page for the shots, so no client setting changed), then `--restore --apply` returned every flag exactly (diff of all scene flags against the dump taken first: empty) and `canvas.draw()` reset the page.
**Not verified:** the night preset in Foundry (the night sky image was not built or pushed), foggy_morning live, `--ground-cast` live, a real player browser with shadowQuality set through the settings dialog, screenshot capture from the panel (the bridge has no screenshot op, so the in-panel preview is the offline approximation `sun_preview.py`: plan view of terrain + building roofs, no trees). Where a live OpenGL fly-through panel would plug in: replace `sun_preview.render()` with the viewer; the input is the same preset dict.
